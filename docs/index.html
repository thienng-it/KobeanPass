Interactive Cryptographic Pipeline

Click on any stage below to inspect how KobeanPass derives keys, isolates memory, wraps credentials, and enforces tamper-resistant double-envelope encryption.

1
Master Password & 32-Byte CSPRNG Salt Input Stage
Password held strictly in memory with ZeroizeOnDrop. Never stored or emitted.
2
Argon2id Key Derivation (MK) Memory-Hard KDF
64 MiB RAM, 3 iterations, 4 parallel lanes producing a 256-bit Master Key. Resistant to GPU/ASIC clusters.
3
HKDF-SHA256 Key Expansion (KWK & AuthKey) Domain Separation
Derives Key Wrapping Key (kobean-kwrap) and fast Auth Verification Key (kobean-auth).
4
Vault Encryption Key (VEK) Unwrapping Independent 256-bit Key
Decrypts the CSPRNG VEK using XChaCha20-Poly1305. Allows master password change without re-encrypting records.
5
Per-Record AEAD Encryption (XChaCha20-Poly1305) AAD Tamper Proof
Each record encrypted with 24-byte random nonce and AAD (vault_id || item_id || schema_version).
6
Storage: SQLCipher Page Encryption AES-256-CBC + HMAC
Entire SQLite database page-encrypted at 4096-byte blocks with HMAC-SHA512 integrity verification.

1. Master Password Input & 32-byte CSPRNG Salt

When you enter your Master Password to unlock or initialize your vault, KobeanPass loads a unique 32-byte cryptographically secure random salt (OsRng). The master password is held in temporary zeroizable memory (zeroize::ZeroizeOnDrop) and never leaves your local CPU.

Salt Length: 32 bytes (256-bit) RNG: OS Hardware CSPRNG Memory: Zeroize + ZeroizeOnDrop

Capabilities

Engineered for Absolute Reliability

Discover the features that make KobeanPass the preferred tool for developers, security researchers, and privacy advocates.

Double-Layer Encryption

Combines page-level SQLCipher (AES-256-CBC with HMAC-SHA512) and record-level XChaCha20-Poly1305 with AAD verification for unmatched protection.

In-Memory Zeroization

All master keys, encryption keys, and unencrypted byte arrays implement Rust's Zeroize + ZeroizeOnDrop to guarantee immediate memory sanitization.

Built-In 2FA / TOTP Engine

Native RFC 6238 / 4226 TOTP generator supporting SHA-1, SHA-256, SHA-512, 6-8 digit tokens, live countdown rings, and QR code importing.

Vault Health & Breach Audit

Audit your vault for duplicate, weak, and stale passwords locally. Optional opt-in Have I Been Pwned check using k-anonymity (5-char SHA-1 prefix).

Clipboard Auto-Purge

Any password or token copied to the system clipboard is automatically scheduled for zero-trace wipe after a configurable countdown (default 30 seconds).

Fast Command Palette

Instantly navigate your entire vault with Cmd+K / Ctrl+K. Filter by folder, tags, favorites, and execute copy actions without touching your mouse.

          Philosophy & Rules
          
The 10 Inviolable Security Invariants

          

            Every pull request and build must strictly obey these architectural boundaries.
          

        


        

          

            
              

                Rule
                Invariant Requirement
                Enforcement Method
              

            
            
              

                1
                Zero Secret Logging
                Secrets (MK, KWK, VEK, plaintext) are never printed in debug strings or logs.
              

              

                2
                No Secrets in Events
                Secrets cross the IPC boundary solely as typed command return values, never event broadcasts.
              

              

                3
                No Secrets in Web Storage
                Plaintext secrets are never stored in Zustand, localStorage, sessionStorage, or IndexedDB.
              

              

                4
                Memory Hardening
                All key material derives Zeroize + ZeroizeOnDrop to guarantee zero leftover memory.
              

              

                5
                Double Encryption
                SQLCipher page-level encryption + per-record XChaCha20-Poly1305 with AAD verification.
              

              

                6
                Audited Crypto Only
                Exclusively audited RustCrypto crates (Argon2, ChaCha20Poly1305, HKDF, SHA2). No custom primitives.
              

              

                7
                Offline Sovereignty
                Zero outbound network requests by default. HIBP audit requires explicit user opt-in (5-char SHA1 prefix).
              

              

                8
                No Unsafe Rust
                Safe Rust only with -D warnings enforced via cargo clippy.

          Questions & Answers
          
Threat Model & FAQ

          

            Technical answers regarding our zero-knowledge design and cryptographic threat model.
          

        


        

          

            
            

              Every encrypted record binds Additional Authenticated Data (AAD) into the Poly1305 authenticator tag containing vault_id || item_id || schema_version. If an attacker moves ciphertext between items or vaults, authentication verification fails instantly.
            

          


          

            
            

              KobeanPass uses an envelope encryption hierarchy. All vault records are encrypted by the random 256-bit Vault Encryption Key (VEK). When you change your master password, we only re-derive the Key Wrapping Key (KWK) and re-encrypt the VEK envelope—avoiding expensive re-encryption of thousands of individual items.
            

          


          

            
            

              KobeanPass uses the k-anonymity protocol. We compute the SHA-1 hash of the password locally and send only the first 5 hexadecimal characters (20 bits) to the API. The API returns a list of matching hashes, and KobeanPass performs the final lookup locally. The full password or hash is never sent across the network.
            

          


          

            
            

              An attacker who obtains the raw file faces two layers of defense: first, the SQLCipher database pages are encrypted with AES-256-CBC and HMAC-SHA512. Second, even if they could bypass SQLCipher, every record inside is separately encrypted with XChaCha20-Poly1305. Cracking requires guessing your master password against Argon2id (64 MiB RAM per attempt).
